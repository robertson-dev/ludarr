# ludarr API

Base: `http://<host>:7979/api/v1`. Every call needs the API key (Settings → General) in `X-Api-Key`, or `?apikey=` for the event stream. Responses are JSON; lists come as `{ items }`.

| Area | Routes | Documented in |
|---|---|---|
| Library | `GET/POST /game` (`POST { source: "manual", game: GameDraft, posterUrl?, bannerUrl?, force? }` adds a game by hand; 409 `{ error, existingId }` when one of that name and year ±1 is already in the library), `GET/PUT/DELETE /game/:id` (a game on several platforms can be asked for in one version: `platform` on `POST /game` and `PUT /game/:id`, one of the game's `platformChoices`' ids such as `arcade` or `x360`, or null for no choice; its searches then take a copy for that platform only, and changing it stops the search under way and starts one for the new version; every game says `platformChoices` and `wantPlatform`, every lookup hit `choices`), `PUT /game/:id/details` (a game added by hand: any GameDraft field; any other game: `aliases` and `searchTerms` only), `PUT/DELETE /game/:id/art/:kind` (poster, banner, hero, logo: an image body ≤ 15 MB or JSON `{ url }`; a kind set here is never replaced automatically), `POST /game/:id/search` (an upgrade search when the game has a copy and its profile allows upgrades; a game players cannot start yet — no copy, or a console dump — that has a way to play searches for that way's game file), `POST /game/:id/refresh` (400 for a game added by hand), `GET /game/lookup?term=` (library games by name or alias first), `GET /wanted/missing`, `GET /wanted/cutoff`, `GET /calendar`, `GET /discover` | `src/api/games.ts` |
| How a game starts | `GET /game/:id/launch` (the copy's start as one whole line, program and arguments, and where it comes from: `by` hand, plan, ludarr or ai; the start found (`auto`); the start set by hand (`set`), whether this copy starts with it (`applied`) and why not (`notApplied`, in the words Save would refuse it with; null when that is not known); `resettable` (a start set by hand, or the copy starts otherwise than found — a way's copy whose way is gone keeps the start set by hand on it, and only Reset is offered); the editor's `fields`; the copy's `programs` with what each one's header and the package's own words say about it, quoted with their source, and its `scripts` with their first comment and what they run (`startable` for a `.bat` or `.cmd`, which can itself be the start; `does`: what it does on a player's PC beyond starting a program; `current` when it starts the copy now); `folders`; `placeholders`; `editable` false with `why` for a console dump; `busy` while the copy is being rebuilt), `GET /game/:id/launch/files?q=` (any file of the copy by any part of its path, at most 200), `POST /game/:id/launch/check { exe, argv?, cwd?, env? }` (`{ errors, warnings, line, needsAhoy }`: what Save would say, changing nothing), `PUT /game/:id/launch { exe, argv?, cwd?, env? }` → `{ item, warnings }` (a .exe of the copy's file list on the disk that is a Windows program, or — the game's own start script — a `.bat` or `.cmd` of the copy with arguments of plain words only (letters, digits and `. _ - + = , : / \ @`; the copy then needs Ahoy 0.11, and `warnings` say what picking a script means and what this one does on a player's PC: administrator rights, a service or driver, the registry, downloads …, each with the line that does it); no other script, no DLL, no file players keep, only `{install}` — and `{content}` on a way's copy —, no path out of the game's folder; applied to the current copy at once: its manifest and `ahoy.json` (written beside the old one and renamed over it), `launch.rev`, `requires`, a history line, the `package` event; kept for the next copy of the same origin: a way's `overrides.launch`, the game's for its PC copies, with the files of the copy its arguments and variables name as `{install}/…` (`paths`), applied when its program, its folder and those files are in that copy and otherwise said as not applied; 400 `{ error, errors }`, 409 while the copy is being rebuilt, for a console dump or a way's copy whose way is gone, 500 when `ahoy.json` cannot be written, with nothing changed), `DELETE /game/:id/launch` (Reset: the start found comes back, also on a way's copy whose way is gone; 404 when nothing was set by hand), `GET /package/:id/launch` → `{ launch, rev, requires, kind }` (a package's start as it is now, cheap: what the launcher asks at Play to take a start changed in place, under the same package id) | `src/api/launch.ts` |
| Activity | `GET/DELETE /queue[/:id]` (a search that took nothing carries `refused`: the releases it found and why each was not taken; one whose download is awaited in the finished-downloads folder carries `waiting.kind` `arrival`, and `waiting.ask { why: late \| lost \| ambiguous, choices }` once it asks), `POST /queue/:id/retry`, `GET /download`, `POST /download/:id/arrival { choice: seedbox \| now \| wait \| again }` (the answer to that question: import it from the seedbox instead, import what has arrived — usenet —, keep waiting, download the same release again; 409 when it cannot be made now, 400 for any other choice), `GET /history` (its events include `left` — a download ludarr held in the finished-downloads folder and let go, nothing of it deleted there — and `removed` — what ludarr took there for a download it imported, deleted), `GET/DELETE /blocklist`, `GET/POST /release` (interactive search + grab; `GET /release?gameId=` asks the game's name, its aliases and its search terms, `?term=&year=&aliases=&terms=` the ones listed; each item's `refusals` says in words why the automatic search would not take it, and `certain` is true when there are none), `GET/POST /import`, `GET /import/:id` (transcript, trace, lesson), `GET /package`, `GET /package/:id/files/*` | `src/api/activity.ts` |
| Settings | `GET/PUT /config` (PUT returns `{ rejected, changed, errors }`, 400 on errors; `LUDARR_ARRIVALS`, "Finished downloads land in", is the folder everything downloaded ends up in — downloads/finished, `/arrivals` by default: while it is set and there, a finished download is found there by its name and imported in place, never transferred — and once it is imported (its search done with it, the game's copy in the library checking out, nothing else reading it), exactly the files ludarr took there that its download client's own list shows to be that download's (a torrent's files; what NZBGet's folder held on the seedbox, read through the client's remote path mapping) are deleted, then the folders that leaves empty inside the download's own folder (never that folder itself, a category's or anything else in it), the way Radarr and Sonarr move what they import out of it; anything else it took stays, an import that failed or was cancelled deletes nothing, and nothing is deleted while the folder is not the one set, is not there, or is an rclone mount of the seedbox; saved empty, it is off — a download client's remote path mapping onto that folder is not used while it is on, and the health list says so), `GET /config/host`, `POST /config/apikey`; per kind (`indexer`, `downloadclient`, `metadata`, `importer`, `runtime`, `notification`): `GET /<kind>`, `GET /<kind>/schema`, `POST /<kind>`, `PUT/DELETE /<kind>/:id`, `POST /<kind>/test`, `POST /<kind>/:id/test`; `profile`, `rootfolder`, `plugin` | `src/api/settings.ts` |
| System | `GET /system/status`, `GET /health`, `GET /system/task`, `POST /system/task/:name`, `GET /log`, `GET/POST/DELETE /system/backup`, `GET /system/events` (SSE) | `src/api/system.ts` |
| Art | `GET /art/game/:id/poster`, `/banner` (the game's own art first, then resolved art, then a placeholder), `/hero`, `/logo` (its own only; 404 otherwise), `GET /art/title/:id/poster`, `GET /art/steam/:appid/poster`, `GET /art/url?u=` — served without the key and read-only; art is set through `/game/:id/art/:kind` | `src/api/art.ts` |
| Catalog | `GET /catalog/titles`, `GET /catalog/titles/:idOrSlug`, `GET /catalog/runtimes`, `GET /catalog/sources`, `POST /catalog/sources/:id/refresh` | `src/api/catalog.ts` and `docs/catalog-api.md` in the Ahoy repo |
| Ways to play | Plans: `GET/POST /plan`, `GET/PUT/DELETE /plan/:id` (`?force=1` takes its ways and system files along, and its carry runs stop with the jobs they started; a PUT that changes the program, tools or repo is 409 while a build of the plan is queued or running), `POST /plan/:id/check` (latest release → ready or broken; 429 at GitHub's hourly limit), `POST /plan/:id/needs/:i/file?name=` (raw body) and `/needs/:i/path { path }`. Ways: `GET/POST /game/:id/ways` (a way added is carried through by a run; `POST { planId, content?, overrides?, force? }`: 409 `{ error, wrongGame: true }` for a recomp or port plan whose `content.search` does not name this game, unless `force`; a way's `job` is its build, or the build of its program for this game), `PUT/DELETE /way/:id`, `POST /way/:id/build { replace?, repin? }` (202 `{ job }`: one press builds — a make first when the way's file is made from the game's copy or a kept dump, the program built for this game first when the plan builds it per game, each queuing the assemble when it ends (a way whose file is still the game's copy: the assemble takes it in, then the program's build for this game follows by itself, and the assemble after it); 409 with `blockers`, or `current: "native"`; a way's `copy` is the game's copy judged in place — `serves` direct, make, no with the words why, or unknown while it is looked at — and its `run` the open carry run), `POST /way/:id/accept-file { contentId }`, `POST /way/:id/find-files` (202 `{ request, duplicate }`: a search for the way's game file through the request queue — its console only, the file taken only when a hash, a serial its bytes carry or the dump lists prove it, then the way built; first the serials the catalog and the dump list give the game join an emulator way's own, never one the admin took off it with `PUT /way/:id`; 409 with the reason when the way has its file, is being built, its plan is not ready, it needs no file or PC data, or a file a search brought that this way cannot tell apart either waits for a look). Game files: `GET /content?gameId=|planId=`, `POST /content?gameId=&name=&platform=&wayId=` (raw body, up to CONTENT_UPLOAD_MAX_GB), `POST /content/path { path, gameId, wayId? }` (202 `{ job }`; its message ends `— not the file <plan> needs: <why>` when the file does not fit the way named), `GET /content/:id/check?wayId=`, `DELETE /content/:id`. Jobs of every kind (`make` too): `GET /jobs?kind=`, `POST /jobs/:id/cancel` (your cancel holds the run that started the job until you resume it). `POST /plan/:id/check` readies a plan built from source with each game's file once it validates | `src/ways/api.ts` |
| Uploads | A game's files sent from the admin's own PC, for any game (an archive, an installer with its files, a whole folder): `POST /game/:id/upload { name, files, bytes, wayId?, replace? }` (201 `{ item }`; `files` and `bytes` announce how many files and their size together; with `wayId` it is that way's game file, else the game's copy; 200 `{ item, resumed: true }` when the very same pick is under way already; 409 `{ needsReplace: true }` for a copy while the game plays through a built way, unless `replace`; 507 when the library has no room for it above what it keeps free), `GET /upload?gameId=`, `GET /upload/:id` (`{ item, files: [{ path, size, done }] }`: what is there, whole or in part), `PUT /upload/:id/file?path=&size=&offset=` (a piece of one file as the raw body, appended at `offset`; `{ received, done, item }`; 409 `{ received, done }` when the piece does not start where the file ends: go on from `received`; a newer piece of a file takes over from one whose sender went quiet, a piece that brings nothing for 90 s ends by itself, and 409 `{ busy: true }` means the earlier one has not let go yet: try again in a moment; the web UI sends pieces of 32 MB, one request may carry a whole file up to CONTENT_UPLOAD_MAX_GB), `GET /upload/:id/file?path=` (`{ received, done }`: how much of one file is there, nothing written — what a sender asks after its line dropped), `POST /upload/:id/finish` (202 `{ item, job }` once every file is whole and their number and bytes are as announced: an import for the game's copy — its manifest's `source.protocol` is `upload`, its format `uploaded`, and no upgrade search replaces it — or a content job for a way's game file), `POST /upload/:id/retry { wayId?, replace? }` (an upload whose job failed, taken in again, the other way too: `wayId: null` for the game's copy), `DELETE /upload/:id` (its files go; one being taken in has its job stopped first). An upload's own files go once its job took it in; one nobody finished, or whose job failed, after 7 days untouched. A search under way for the game stops once an uploaded copy is in the library. `upload` events carry the item, or `{ id, gameId, deleted }` | `src/api/uploads.ts`, `src/uploads.ts` |
| Blocks | A package sent as blocks, so a launcher takes a game in a few requests instead of one per file (src/blocks.ts): each file cut at every MiB, each block named by its sha256. `GET /package/:id` says `blocks: { size, count, digest }` once the package has an index (an import writes it in the read it does anyway; the task `blocks` builds it for packages that have none), else `blocks: null`. `GET /package/:id/blocks`: the index, a 64-byte header (`AHOYBLK1`, u32 block size, u32 files, u32 blocks, 12 bytes of the server's own, the 32-byte digest of the file list) then every block's sha256, files in the manifest's order. `POST /package/:id/blocks { digest, want: [[file, first block, count], …] }` → those blocks in the order asked, as frames: u8 kind (0 as it is, 1 one zstd frame, 255 an error's words, which ends the stream), u32 length (little-endian), payload; a block travels compressed only when that makes it smaller. 404 while the package has no index, 409 `{ digest }` when its files are not the list asked for, 413 for more than 256 MiB or 40,000 runs in one request. `GET /blocks`: how far the library is (`{ packages, ready, blocks, sending, working, waiting, refused }`). |

| Ways from a repo | `POST /plan/construct { repo?, gameId?, planId?, note?, contentId? }` (202 `{ job }`: ludarr's own list of ports and emulators first, the AI importer for the rest; a dry run must pass before a plan is saved; 409 when neither can cover the repo, saying which, and when `planId` or a `note` is given without the AI importer set up; the finished job's `manifest` is `{ planId, wayId?, game? }`; its `tier` is `agent` only once the AI works on it), `POST /plan/:id/build { wayId? }` (202 `{ job }`: a source plan built from its recorded steps and pinned, and its tools; a plan built once per game needs `wayId`; 409 when there is nothing to build, a package is not on the build allowlist, there is no build sandbox, a build of the plan — of that way, for a plan built per game — is already queued or running, or the way named is being built itself, `{ error, job }`), `POST /game/draft { name?, repo? }` (`{ draft: GameDraft, from, fields, inLibrary }`: what ludarr knows about the game, the AI's proposal for the rest), `GET /plan/construct/:jobId/shot/:n` (a dry run's smoke-start screenshot). Watch a job with `GET /import/:id` and the `build` events | `src/ways/construct-api.ts` |

## Carry runs (`src/ways/carry-api.ts`)

A carry run carries a repo all the way to a game members install, with no click: one row per (plan, game), started by a construct job that saves a plan, by a way being added, by the backfill (every way not built yet and every recomp or port plan without a way, at boot and daily; a plan whose game is not in the library starts held, asking to go ahead) or by the admin. A game that already plays another way (a PC copy, another way's build) is held with a go-ahead in the replace form ("Build <game> with <plan>?": building it replaces that copy and removes its files) before anything is fetched or built: `{ go: true }` carries it on from the plan with replace and no more clicks, `{ go: false }` stops it; while held it looks every 10 minutes whether the game still plays that way, and carries on by itself once it does not. Before a new search the run offers the way the game's earlier downloads still on the server (a content job with `earlier: true`: only read, never marked imported or removed), each once under a content plan (one ludarr itself could not take in: twice, then passed by — it never holds up the search), and never one a search or an import still holds (the run waits for that search instead). A run is admin-only: `RunView` in `src/ways/types.ts` (phase `plan · game · file · build · check · done`, state `active · waiting · asking · held · done · stopped`, a rail per phase, what it is doing now — `now.text` is the child job's own words while it runs, and while it waits in the queue the runner's reason (room, a build user) or that it waits for its turn, the search's stage while its search runs, and why it waits when nothing of its own is under way (an inbox entry still arriving, a step to be tried again at a time it names); `now.progress` its real progress once it has started, else null —, what it asks, its AI budget; the step a run ends on names the job that built the way, whose trace holds the check); `run` events carry it without its steps. The handlers never move a run themselves: they record an intent and the run applies it at once. Errors are `{ error }` in plain words with 400, 404 or 409.

| Route | What it does |
|---|---|
| `GET /runs?gameId=&planId=&wayId=&open=1` | `{ items: RunView[] }` without their steps, newest first; `open=1`: the runs that have not ended |
| `GET /run/:id` | `{ item: RunView }` with its steps (`RunStep[]`: when, who — ludarr, the AI, you —, what, the outcome, the job, request or file it was about, its proof) |
| `POST /run/:id/stop` | `{ item }`: the run stops; the jobs it started are cancelled and the way's search it started goes too; 409 when it has ended |
| `POST /run/:id/retry` | `{ item }`: looks again now — a run asking for its game file reads the inbox and searches again from scratch; a run held by your cancel resumes; a step waiting to be tried again runs now; 409 when it has ended |
| `POST /run/:id/answer` | `{ gameId }` (the library game the plan plays), `{ newGame: true }` (add it from the plan's own draft) or `{ go: true \| false }` (a held run: go ahead — for the replace form, build it over what the game plays — or not now: the run stops and nothing is removed) → `{ item }`; 400 for any other body, 404 for no such game, 409 when the run is not asking that |
| `POST /run/:id/tell` | `{ text }` (up to 2000 characters): what the admin tells the AI in their own words — what the plan has wrong, what to do instead. One AI round ("told") reworks the plan as they say, outside the run's rounds and with tokens of its own: what they tell it to accept or drop needs no evidence, a port they say needs no game file may lose its game file plan, and documented installer preparation runs on the server with `program.perGame`. Private inputs use `needs[].build: true`, are available under `{needs}/<place>`, and never enter the player package. A unique matching stored upload is reused; a missing input is asked for directly. The run then takes the plan up from the start. 202 `{ item }`; 400 nothing said or too long; 409 the run has ended, waits for a go-ahead, or the AI importer is not set up |
| `POST /way/:id/carry` | `{ replace? }` → 202 `{ item }`: "Make it playable" — the way's open run, else a new one; a held run is lifted (with `replace`, one held by the replace question goes on from the plan); `replace` lets it build over a PC copy the game has (ask first); 409 when the way is built |
| `POST /plan/:id/carry` | `{ gameId? }` → 202 `{ item }`: the plan's open run for that game (or for the game it plays), else a new one |
| `POST /content/:id/free-duplicate` | `{ freedBytes }`: a kept file that is the same bytes as the game's copy becomes a hard link to the copy's file (lossless, one volume; the re-read can take minutes); every run that asked for room looks again at once (room on the library is room for every game on it); 409 with the reason when it is not such a duplicate or a way using it is being built, 507 when there is no room to read it again |
| `GET /check-shot/:name` | a check's screenshot (`image/png`; name `[a-z0-9-]+.png`, else 404) |

Shapes: a library game is `serializeLibraryGame()` in `src/library/games.ts` (status: `missing · searching · downloading · importing · available · unreleased · unmonitored · failed`; `source` steam | igdb | catalog | manual, `aliases`, `searchTerms`, `customArt` (the art kinds set by hand) and `customArtAt` (a cache key for them); `file.kind` native | rom | recomp | port | emulated, `file.requiresLauncher`, `file.start` (the whole start line, program and arguments; null for a console dump; for the admin: a client that passes games on to its members drops it — Ahoy's server does from its release of 2026-11-09, so that release goes out before or together with a ludarr that sends it) and `file.launchRev` (when the start was last set or reset by hand: an opaque stamp a client compares with the one it installed)); a game described by hand is `GameDraft` in `src/ways/types.ts`; a plugin instance is `serializeInstance()` in `src/plugins/registry.ts`; settings fields are `Field` in `src/plugins/types.ts`.

Clients (a launcher, a storefront): add games with `POST /game { source: "steam"|"igdb"|"catalog", id }` (or `{ source: "manual", game }`), watch `/system/events` for `request`, `job`, `package` and `game` events, and install an imported copy by listing `GET /package/:id` (manifest with every file and its sha256) and streaming `GET /package/:id/files/<path>` (Range supported). How a copy starts can change in place (the same package id, the same files, a new `launch.rev`): ask `GET /package/:id/launch` at Play to take it.
